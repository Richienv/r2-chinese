# Learning engine v2 — 14 November 2026

The existing `yulu.hsk4a.v1` account keys remain the source of persistence. Opening v2 snapshots the raw prior value at `.before-v2` before any write. Cloud rows are backed up locally at `.server-before-v2` before synchronization. Existing word IDs, schedules, lesson completion, XP and semantic checkpoints are retained. No retroactive review dates are invented.

FSRS 6 is pinned through ts-fsrs 5.2.3 (Node 22 compatible), retention 0.90, maximum interval 365 days, deterministic intervals. Recall, reading, listening, speaking and writing have separate schedules; the legacy card map projects the earliest due skill for compatibility. Placement requires an unassisted checked answer; a passing first placement sets a minimum 14-day baseline. Early successful practice cannot inflate intervals. Self assessment and verified production remain distinguishable. Unreadable handwriting is not a failure.

Events are immutable and UUID-deduplicated. Undo adds a tombstone and derives the earlier schedule/mastery; XP and daily credit are reversed. A compare-and-swap cloud write retries after merging the current server row. Separate lesson/drill credit events preserve additive XP across devices. Storage failures block progress mutation and expose an export instead of silently pretending to save. Resets retain a prior snapshot and a reset epoch so a stale device cannot resurrect the deck. Star removals have their own timestamped state.

Only HSK 4, Jiaocheng 2 and Workplace Mandarin are primary learning paths. Books remain a secondary reading shelf. Magang AI, Jiayin and general interview source/data files and progress are retained as archives; their library and current-progress entries are removed.

Lesson production starts with one missing word; full-sentence practice remains selectable. Open writing starts with one short sentence. Character alignment preserves matching runs and exposes only changed spans as inputs. It describes reference differences, not an independent grammar verdict. Alternative phrasing requires the existing grammar reviewer; lack of a reviewer stays unverified. Guided answers and repairs cannot be recorded as unaided mastery. Correct supplied sentence fragments do not create new recall events for every visible word.

Native recordings are preferred directly, with per-track retry cooldown, cancellation, timeout and completion checks. Playback waits for metadata and the requested seek position before starting. The original voice configuration, recordings and default speaking rates are preserved at Richie's request. Neural clips use a bounded optional device cache. The source is visible on the player; device fallback selects Mandarin locales. Long text is chunked without silently truncating narration. No new paid voice provider or API key is introduced.

Rollback: keep the original browser origin and account namespace. Export progress from Profile before rollback. Restore `.before-v2` only as an explicit recovery step after preserving the current main value; it intentionally represents the pre-upgrade snapshot, not later v2 work. Code rollback is independent of progress recovery. Archived course keys and writing drafts are included in the exported device backup. Do not clear storage, reset all courses, or replace cloud state with an empty/local-only record.

Release gate: automated tests and production build, mobile/desktop visual checks, correct/wrong/repair/Undo/reload flows. Real account cloud conflict behavior and physical iPhone audio/motion require a controlled rollout. Source-level and simulated checks are not a native-speaker listening review.

Implementation validation: 260 automated tests passed; TypeScript and production build passed. Browser fixtures verified preservation of legacy XP/completions/checkpoints, 14-day placement, Undo, partial character repair, guided answers recorded as assisted, and recorded playback at the manifest segment position. The narrow app column was inspected in the browser; the viewport override did not take effect, so a true 390px viewport and a physical phone remain unverified. Existing large content chunks still produce a Vite size warning, although secondary screens and courses are now lazy-loaded. No production deployment or live account mutation was performed during these checks.
